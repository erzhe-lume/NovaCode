# Skill 系统 Spec

## 背景

用户反复输入同样的提示词（生成 commit、审查代码、跑测试等），每次都手动重敲，既费时又容易不一致。第 10 章的命令系统只能承载写死在代码里的预设提示词，无法让用户扩展；而可复用的 AI 操作其实可以沉淀成一份「能力包」。

本步引入 Skill 系统：把可复用的 AI 操作封装成独立的 Markdown 文件，打上元信息，支持「两阶段加载」和「两种执行模式」。启动时 Agent 只看到 Skill 的名字和一句说明；要用时再通过一个内置工具按需把完整指令和专属工具加载进来；同时用工具白名单收窄当前可用工具，提升模型选对工具的准确率。

## 目标

- 单个 Skill = YAML frontmatter + Markdown 正文，正文是给模型看的 SOP 指令，支持参数占位符。
- 三级存放（项目 > 用户 > 内置），同名按优先级覆盖，解析失败的单文件跳过不阻断。
- 两阶段加载：启动只注入名字 + 一句说明；按需用内置工具加载完整指令 + 专属工具。
- 激活后的完整指令钉在环境上下文最显眼位置，每轮重建都在，多个 Skill 可同时激活。
- 两种执行模式：共享当前对话（结果留在主历史）／独立对话跑完摘要回流（可配置带多少历史）。
- 工具白名单收窄可用工具；加载工具是系统级的、不受白名单约束。
- 加载完自动注册斜杠短命令，支持热更新；清空对话也清空激活的 Skill；内置 commit / review / test 三个样板。

## 功能需求

- **F1 Skill 定义格式**：单个 Skill 由 YAML frontmatter（元信息）+ Markdown 正文（SOP 指令）构成。frontmatter 字段：唯一名字、一句说明、可见工具白名单、执行模式（shared / independent）、独立模式带多少历史、可选指定模型。正文支持参数占位符，激活时用用户传入的内容替换。

- **F2 三级存放与覆盖**：Skill 分三级存放——项目目录 > 用户目录 > 内置，同名按优先级覆盖（项目覆盖用户覆盖内置）。加载时逐级扫描、合并，单个文件解析失败只跳过该文件、不阻断其余。

- **F3 两阶段加载**：第一阶段，启动时只把每个 Skill 的名字和一句说明注入对话（菜单）；第二阶段，模型按需调用一个内置工具，把该 Skill 的完整指令和专属工具加载进来。

- **F4 激活与钉住**：激活后的完整指令钉在环境上下文最显眼的位置，每轮重建系统提示词时都在；多个 Skill 可同时激活，激活内容并集呈现。

- **F5 两种执行模式**：shared 模式在共享当前对话中执行，结果留在主历史；independent 模式开独立对话跑完，再把摘要回流主历史，独立模式可配置带多少条近期历史进去。

- **F6 工具白名单**：Skill 用白名单收窄当前可用工具；启动期若白名单引用不存在的工具立即报错退出；加载 Skill 的内置工具是系统级的，不受白名单约束、始终可用。

- **F7 斜杠命令与生命周期**：Skill 加载后自动注册成斜杠短命令（可带参数）；支持热更新；清空对话时一并清空激活的 Skill；内置 commit、review、test 三个样板。

- **F8 目录型 Skill**：一个目录里放「入口 Markdown + 专属工具的 schema + 实现脚本」整套作为一个能力包；激活目录型 Skill 时，其专属工具一并注册。

## 非功能需求

- **N1 两阶段省 Token**：启动只注入名字 + 说明（远小于完整 SOP），完整指令按需才进上下文；未激活的 Skill 不占用上下文。

- **N2 不破坏稳定前缀缓存**：激活内容的注入点位于稳定前缀之后，激活与否只改变可变段，稳定前缀字节不变、缓存命中不受影响。

- **N3 启动期失败即退出**：白名单引用不存在的工具，在启动阶段抛出致命错误并退出，不延迟到运行时。

- **N4 坏文件降级**：单个 Skill 文件解析失败（frontmatter 缺失 / YAML 非法 / 缺名字或缺说明）只跳过该文件并保留提示，不阻断整体加载。

- **N5 行为确定**：Skill 的执行模式、白名单、参数替换规则都是声明式元信息，不依赖模型即兴判断；同名冲突按固定优先级裁决。

## 不做的事

- Skill 市场分发（下载、安装远程 Skill）。
- Skill 版本管理（多版本共存、版本锁定）。
- frontmatter 里「指定模型」字段运行时切换客户端：本步只解析并保存该字段、在列表里展示，不据此切换当前模型。
- 独立模式下的异步非阻塞执行：本步独立模式同步跑完再回流（阻塞提交线程），异步化留后续。

## 验收标准

- **AC1**：存在一个合法 Skill 文件时，启动后系统提示词的 Skill 段只含其名字与一句说明，不含完整 SOP 正文。
- **AC2**：调用加载工具（参数 = 该 Skill 名字）后，返回其完整 SOP 正文；该 Skill 进入激活态。
- **AC3**：激活后下一轮系统提示词里钉有该 Skill 的完整正文，且位于自定义指令 / 记忆之前（更靠前）。
- **AC4**：多个 Skill 同时激活时，系统提示词里同时钉有它们的完整正文。
- **AC5**：白名单引用不存在的工具时，启动进程以非零退出码报错退出。
- **AC6**：激活带白名单的 Skill 后，可用工具收窄为白名单工具 + 加载工具；加载工具在收窄后仍可用。
- **AC7**：shared 模式 Skill 通过斜杠命令执行后，其 SOP 以用户消息形式进入主历史并启动 Agent。
- **AC8**：independent 模式 Skill 执行后，主历史只多出摘要（不含子对话的工具调用细节），摘要按配置带上指定条数的近期历史。
- **AC9**：Skill 自动注册的斜杠命令可带参数，参数替换进 SOP 正文占位符。
- **AC10**：清空对话（/clear 与 /new）后，激活的 Skill 被清空。
- **AC11**：项目目录同名 Skill 覆盖用户目录与内置；用户目录覆盖内置。
- **AC12**：解析失败的单文件被跳过，其余 Skill 正常加载、进程正常启动。
- **AC13**：目录型 Skill 激活后，其专属工具可被调用。
