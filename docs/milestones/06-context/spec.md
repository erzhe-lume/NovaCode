# 上下文管理 Spec（第 8 章）

## 背景
NovaCode 是一个会连续调用工具、跨轮累积对话的终端 Agent。工具结果（尤其是 ReadFile / Grep / Bash 输出）是 Token 大头，长时间任务会让累积对话逼近模型上下文窗口上限，最终请求因超限失败、Agent 瘫痪。

当前没有上下文管理：对话只增不减，没有压缩、没有存盘、没有窗口告警。本章给 Agent 装上两层压缩能力，让它在有限 Token 预算里长时间干活。

## 目标
- 工具结果可控地存盘降重，用户原始消息尽量原文保留。
- 对话逼近窗口上限时自动生成结构化摘要，压缩早期历史、保留近期原文。
- 用户可手动触发压缩；摘要连续失败会熔断，不陷入死循环。
- 不引入精确 tokenizer，用「锚定上次 usage + 增量按字符估算」的近似即可。

## 功能需求

- **F1（压缩目标）：** Token 压缩从工具结果入手；用户的原始消息（USER 角色的真实输入）在任意压缩后保持原文不变，不被摘要改写。

- **F2（单条存盘，预防层）：** 单个工具结果估算 Token 超过单条阈值时，把完整内容写到磁盘文件，对话里只保留「预览片段 + 文件路径」，供模型后续按需重读。

- **F3（批量存盘，预防层）：** 同一轮（一条 assistant 工具调用消息产生的所有 tool 结果）的工具结果估算合计超过批量阈值时，按体积从大到小依次存盘，直到剩余合计回到阈值以内。

- **F4（结构化摘要，兜底层）：** 整体对话估算 Token 逼近窗口上限时，调用 LLM 生成一份结构化摘要，替换较早的消息；从尾部按 Token 往回数，保留约 1 万 Token 的近期原文（且至少保留 5 条消息）。摘要按固定几个部分组织。

- **F5（摘要 Prompt 约束）：** 摘要请求必须明确禁止模型调用任何工具；并要求先输出分析草稿、再输出正式摘要，草稿在提取后丢弃，只保留正式摘要进入对话。

- **F6（边界消息）：** 压缩完成后，在摘要与近期原文之间追加一条边界提示，明确告知模型：需要文件细节时用 ReadFile 重新读取，不得仅凭摘要臆测代码或文件内容。

- **F7（手动触发）：** 用户可手动触发一次压缩（无论当前是否逼近窗口），结果以提示形式反馈。

- **F8（熔断）：** 摘要连续失败达到 3 次后熔断，自动压缩暂停；手动触发仍可尝试，成功即复位。

- **F9（Token 估算）：** 用「锚定上一次 API 返回的输入 usage + 对增量按字符数估算」的近似，不实现精确 tokenizer。

- **F10（触发时机）：** 每次发起 LLM 请求前，先执行预防层（管单条消息大小），再判断是否需要兜底层（管累积历史长度）。

- **F11（安全余量）：** 自动触发保留 13K Token 安全余量防估算误差；手动触发余量收窄到 3K Token（用户主动要求压缩）。

## 非功能需求

- **N1：** 用户原始消息在压缩后逐字节不变。
- **N2：** 压缩失败（存盘失败、摘要调用失败）不得导致 Agent 崩溃或退出，应降级为「不压缩、继续跑」并给出提示。
- **N3：** 存盘的完整内容可通过现有文件读取能力重新读回，路径可被模型理解。
- **N4：** 压缩逻辑对 provider 协议透明（openai-compat 与 anthropic 均可用）。

## 不做的事

- 不做精确 tokenizer（不接 tiktoken / cl100k 等），仅近似估算。
- 不做摘要策略的机器学习优化（不训练、不调权重）。
- 不做窗口动态预测 / 滚动窗口外的其它压缩策略。
- 不做跨会话持久化摘要（摘要只存在于当前会话内存历史中）。
- 阈值/余量/窗口暂以常量默认值内置，除上下文窗口外不暴露到配置。

## 验收标准

- **AC1：** 单个工具结果超阈值后，其完整内容写入磁盘文件，对话里该消息被替换为「预览 + 文件路径」。（验证：构造超长工具结果，观察存盘文件存在、历史内容变短且含路径）
- **AC2：** 单条消息工具结果合计超阈值时，按体积从大到小存盘，剩余合计回到阈值内。（验证：构造多个大小不同的工具结果，观察存盘的是最大的那几个）
- **AC3：** 对话逼近窗口上限时生成结构化摘要，早期消息被摘要替换、近期约 1 万 Token 原文保留、且出现边界提示消息。（验证：构造长历史触发压缩，观察历史结构）
- **AC4：** 任意压缩前后，历史中所有 USER 原始消息内容逐字节一致。（验证：对比压缩前后的 USER 消息内容）
- **AC5：** 手动触发命令能立刻执行一次压缩并给出结果反馈。（验证：输入 /compact，观察反馈与历史变化）
- **AC6：** 摘要连续失败 3 次后，自动压缩不再触发；手动触发成功一次后复位。（验证：连续 3 次让摘要失败，观察后续请求不再尝试；再手动成功，观察恢复）
- **AC7：** 摘要输出包含固定部分（任务目标 / 已完成工作 / 关键决策与结论 / 当前状态 / 待办事项），且分析草稿不残留在对话历史中。（验证：检查摘要消息内容与结构）
