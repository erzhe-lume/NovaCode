# 记忆与持久化 Spec（第 9 章）

## 背景

前八章让 NovaCode 能对话、能调工具、能管理上下文，但每次启动都是一张白纸：项目背景（技术栈、代码规范）、用户偏好、上次聊到哪，全靠用户重新交代。第 9 章要解决「每次失忆」的问题，让 Agent 在新会话启动时自动恢复项目知识和用户偏好，从「越用越懵」变成「越用越懂你」，中断之后也能平滑接着用。

实现靠三套机制分层管理「工作记忆」和「长期记忆」：

| 机制 | 记忆层级 | 内容 | 存哪 |
|------|---------|------|------|
| 项目指令文件 | 长期（手写、稳定） | 技术栈、代码规范、注意事项 | 三个位置各一份 Markdown |
| 会话存档 | 工作（逐轮增长） | 每轮对话 + 工具调用链 | `sessions/` 下 JSONL |
| 自动笔记 | 长期（自动沉淀） | 用户偏好、纠正、项目知识、参考 | `memory/` 下 Markdown + 索引 |

## 目标

- 启动即恢复：项目指令文件与自动记忆索引在请求处理前就进入上下文，Agent 一上来就「读过」项目背景与用户偏好。
- 会话可续：会话以 JSONL 追加落盘，崩溃最多丢最后一行；重启自动续上最近会话，异常行安全跳过。
- 越用越懂：每轮自然结束后异步把值得记住的事沉淀成笔记，去重交给 LLM，长期记忆跨会话累积。

## 功能需求

- F1: 项目指令文件按三层加载——项目根、项目根下 `.mewcode/`、用户目录 `~/.mewcode/` 各一份手写 Markdown；项目级高于用户级，高优先级排前面拼接，让模型优先遵循。
- F2: 指令文件支持 `@include` 引用其他文件，同时满足三个护栏：限制嵌套深度、用 visited 集合防循环、拦截跳出项目目录的路径。
- F3: 拼接后的指令文件内容注入 System Prompt（复用第 5 章预留的 customInstructions 槽），随稳定前缀之后追加。
- F4: 会话以 JSONL 追加写落到 `sessions/` 目录，每会话一个文件；会话 ID 用 `YYYYMMDD-HHMMSS-xxxx`（随机后缀防同秒撞车）。追加快、崩溃最多丢最后一行。
- F5: 不单独维护会话 meta 文件；需要 ID/标题/消息数时直接扫 JSONL 现算，少一份要同步的状态。
- F6: 会话恢复处理五类异常——坏行跳过、工具调用没配上结果时截断、token 超限先压一次、隔太久插一条时间跨度提醒、30 天以上过期会话定期清理。
- F7: 自动笔记分四类（用户偏好 user / 纠正反馈 feedback / 项目知识 project / 参考资料 reference）；每轮 Agent Loop 自然停下后（模型最终回复无工具调用）异步调 LLM 提取更新，去重交给 LLM 判断。
- F8: 用户级与项目级笔记分开存：`~/.mewcode/memory/` 存 user/feedback，项目 `.mewcode/memory/` 存 project/reference；每条笔记一个带 frontmatter 的 Markdown，另有一份 MEMORY.md 索引。
- F9: 记忆索引（两份 MEMORY.md 拼接）在处理请求前注入上下文，索引文件控制在 200 行 / 25KB 以内。
- F10: 提供 `/new` 命令开始全新会话（清空历史、起新会话 ID）。

## 非功能需求

- N1: 自动笔记异步执行，不阻塞 Agent 循环与 UI 渲染。
- N2: 会话 / 记忆的写盘失败一律静默降级，绝不打断正在进行的对话。
- N3: System Prompt 稳定前缀字节不变——指令与记忆注入在固定模块之后，前八章建立的缓存命中不被破坏。
- N4: 恢复逻辑容错：文件缺失、目录不可读、单行损坏都只影响对应部分，不崩溃。

## 不做的事

- 向量数据库、RAG 检索（留给后续章节或专门项目）。
- 团队记忆同步 / 多 Agent 协作。
- 独立的记忆整理（consolidation / dream）后台任务——本章只做逐轮提取 + LLM 去重。
- 指定某个历史会话手动恢复（本章只自动续最近会话；会话列表仅展示）。
- 思考块（thinking）的持久化——跨会话恢复用不上。

## 验收标准

- AC1: 三层指令文件都存在时，按「项目根 → .mewcode/ → ~/.mewcode/」顺序拼接进 system prompt；只存在部分层时缺省不报错。（F1/F3）
- AC2: `@./` 相对引用正确展开；`@include` 循环引用与超深嵌套被拦截，不无限展开。（F2）
- AC3: 跳出项目目录的 `@include`（如 `@../outside.md`、`@/etc/xxx`）被拦截，原始行保留。（F2）
- AC4: 一轮对话（含工具调用链）追加写入单个 JSONL；重启能读出相同条数并正确还原 role 与工具配对。（F4）
- AC5: 会话 ID 形如 `20260808-111931-xxxx`，同秒两次生成不重复。（F4）
- AC6: 损坏的 JSONL 行被跳过、不导致加载崩溃；工具调用无对应结果的会话在缺口处截断、不留孤儿调用。（F6）
- AC7: 恢复一个超长会话时只压缩一次；恢复一个久未活跃会话时注入时间跨度提醒。（F6）
- AC8: 超过 30 天未修改的会话文件被自动删除。（F6）
- AC9: 会话 ID / 首条消息 / 消息数能通过扫 JSONL 算出，无需任何 meta 文件。（F5）
- AC10: 一次自然结束的对话后，异步生成笔记落到正确目录（user/feedback → 用户级，project/reference → 项目级），MEMORY.md 索引同步更新。（F7/F8）
- AC11: 记忆索引（两份 MEMORY.md）注入 system prompt，超 200 行或 25KB 时被截断并带警告。（F9）
- AC12: `/new` 清空历史并开启新会话文件，后续消息写入新文件。（F10）
