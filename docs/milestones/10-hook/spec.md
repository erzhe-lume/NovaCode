# Hook 系统 Spec（第 12 章）

## 背景
做完 Skill 系统（ch11）后，NovaCode 已能多轮自主干活、在权限护栏内调工具、按需加载可复用操作。但 Agent 生命周期里仍有一类「触发条件明确、动作固定」的重复工作靠人手动盯：写完代码要手动跑格式化、高危命令要人工盯、会话开始要手动贴一段固定上下文。这些工作有三个共同点——**什么时候做是明确的**（写完文件后 / 调工具前 / 会话开始时）、**做什么是固定的**（跑某条命令 / 注入某段话 / 发个通知）、**做起来是机械的**（没有判断成分）。

ch12 给 NovaCode 装上 **Hook 系统**：在 Agent 生命周期的关键节点上挂自动化动作，用「事件 + 条件 + 动作」三要素声明一条规则。事件到了、条件命中，动作就自动跑——格式化、拦截、上下文注入都不用再手动盯。工具执行前的事件还能**拦截**：基于工具参数做细粒度安全策略，拦下后把拒绝原因当工具结果回灌给模型，让模型自己调整。这是把「重复劳动」从人工搬给机器的关键一跃。

## 目标
- **三要素规则**：一条 hook = 事件（何时触发）+ 条件（是否触发，可省略）+ 动作（做什么）；事件与动作必填，条件省略即无条件触发。
- **四层生命周期事件 + 少量系统级事件**：会话级、轮次级、消息级、工具级四层，外加系统级事件，覆盖 Agent 从启动到退出、从一轮到一次工具调用的关键节点。
- **条件复用权限匹配语法**：叶子条件支持精确 / 反向 / 正则 / glob 四种匹配，逻辑组合用「全部满足」或「任一满足」二选一、不混用。
- **四种动作**：执行 shell 命令、注入提示词、发 HTTP 请求、启动子 Agent（本章先占位）。
- **工具前拦截**：`pre_tool_use` 可基于工具参数拦截，拒绝原因作为该次工具调用的结果回灌，Agent 据此调整，Loop 不中断。
- **执行控制**：只跑一次、后台异步、命令超时；拦截类事件不允许异步。
- **失败不中断 + 声明式配置**：Hook 自身失败只记日志、绝不中断 Agent 主流程；规则从 YAML 声明式加载并**集中校验**（聚合全部错误）。

## 功能需求

- F1: 三要素规则
  一条 hook 规则由三要素描述：**event**（触发时刻，必填）、**if**（条件表达式，可省略表示无条件触发）、**action**（动作类型 + 各自字段，必填）。event 或 action 缺失、event 非法、action 字段不完整，都属于配置错误，由集中校验聚合报告。if 省略时该 hook 在该事件每次发生时无条件触发。

- F2: 生命周期事件四层 + 系统级
  事件覆盖四个生命周期层 + 系统级，共 9 种：

  | 层 | 事件 | 触发时刻 |
  |----|------|---------|
  | 系统级 | `shutdown` | 程序退出前 |
  | 会话级 | `session_start` | 新会话创建时（含程序启动的首个会话、`/new` 切换） |
  | 会话级 | `session_end` | 会话结束 / 切换前 |
  | 轮次级 | `turn_start` | 每轮 Agent 开始前（用户提交后、首次调用模型前） |
  | 轮次级 | `turn_end` | 每轮 Agent 结束（Loop 完成）时 |
  | 消息级 | `pre_send` | 向模型发送消息批次前 |
  | 消息级 | `post_receive` | 收到模型响应后 |
  | 工具级 | `pre_tool_use` | 工具执行前（**可拦截**） |
  | 工具级 | `post_tool_use` | 工具执行后 |

  未知事件名属配置错误，由集中校验报告。

- F3: 条件表达式
  `if` 是一段字符串条件表达式，叶子条件支持四种匹配操作符，**复用权限规则的匹配语法**：
  - `==` **精确**：`tool == "Bash"`
  - `!=` **反向**：`tool != "Read"`（不等于）
  - `=~` **正则**：`args.command =~ /rm -rf/`（部分匹配即命中，非全串匹配）
  - `=*` **glob**：`file_path =* "src/*.go"`（glob 语义复用权限规则：路径变量下 `**` 跨目录、`*` 不跨目录；其余变量 `*` 匹配任意字符）

  变量引用：`event`、`tool`、`file_path`、`message`、`args.<字段名>`（工具参数）。无操作符的裸变量表示「该变量非空即为真」。多个叶子条件用 `&&`（全部满足）或 `||`（任一满足）组合，**同一条条件内二选一、不混用**；出现混用属配置错误。

- F4: 四种动作
  | 动作 | 字段 | 行为 |
  |------|------|------|
  | `command` | `command`（+可选 `timeout`） | 通过 shell 执行命令，注入事件上下文环境变量；支持模板变量替换与超时 |
  | `prompt` | `message` | 注入提示词：把 message 在该事件的语义位置注入到发给模型的上下文（会话级/轮次级注入上下文；工具级/消息级作为反馈回显） |
  | `http` | `url`/`method`/`headers`/`body` | 发 HTTP 请求（默认 POST、JSON），支持模板变量替换与超时 |
  | `agent` | `message`（或 `command` 兜底） | 启动子 Agent，**本章先占位**：未注册执行器时返回明确错误，不真实运行 |

- F5: 工具前拦截
  `pre_tool_use` 事件支持 `reject`：命中 reject 的 hook 拦下该次工具调用，**工具不执行**，拒绝原因（动作输出，为空时用默认文案）作为该次工具调用的结果回灌给模型，Agent Loop 继续、模型据此调整策略或换路径。非 `pre_tool_use` 事件上的 reject 无效。

- F6: 执行控制
  每条 hook 可声明三种执行控制：`once`（同一会话内按 id 去重，只触发一次）、`async`（后台异步执行、不阻塞调用方）、`timeout`（命令 / HTTP 的超时时长，超时强制终止）。**拦截类事件（`pre_tool_use`）不允许 `async`**，声明了异步属配置错误。

- F7: 失败不中断 + 声明式配置 + 集中校验
  Hook 动作执行失败（命令非零退出 / HTTP 失败 / 超时 / agent 无执行器）只记日志，**绝不中断 Agent 主流程**。规则从 YAML 声明式加载，加载时**集中校验**：聚合所有 hook 的配置错误一次性报告，不因第一个错误中断检查；格式非法或校验失败的配置降级为不加载该规则，不崩溃。

## 非功能需求

- N1: 失败不中断——任何 hook 动作失败、超时、异常都不抛出到 Agent 主流程，只记录日志；主流程（模型调用、工具执行、Loop 推进）照常继续。
- N2: 集中校验——配置加载时一次性聚合全部错误（缺 event / 非法 event / 缺 action 字段 / 非法 url / 拦截事件异步 / 条件混用），逐条可读；缺文件视为空规则集。
- N3: 不破坏既有章节——Agent Loop 多轮编排、权限五层流水线、上下文管理、Skill 系统的行为不退化；hook 检查不把只读工具并发退化为串行。
- N4: 跨协议一致——hook 触发与拦截发生在 Agent 编排层，与 Anthropic / OpenAI provider 无关，不改 provider 适配层。
- N5: 代码规范——Java 21 + `-Xlint:all`：`mvn compile` 无明显警告、`mvn clean package` 成功；沿用项目既有风格（record、text block、无多余注释），不引入新工具链。

## 不做的事
- **子 Agent 动作真实运行**——`agent` 动作本章仅占位（未注册执行器返回明确错误），真实运行等 SubAgent 章节对接。
- **只跑一次标记的持久化**——`once` 只在当前会话内内存去重，不跨会话、不落地，重启即清空。
- **Hook 执行顺序的显式优先级**——同一事件的多条 hook 按声明顺序执行，不提供优先级 / 依赖 / 编排机制。
- **条件表达式的括号 / 嵌套 / 混用**——不支持括号改变优先级，不支持 `&&` 与 `||` 在同一条件内混用。
- **钩子间通信 / 上下文传递**——hook 之间不共享状态、不传递中间结果（除通过环境变量与模板变量读取当前事件上下文）。
- **Hook 的图形化 / 交互式编辑器**——规则靠 YAML 手写，不做编辑 UI。
- **网络请求的额外限制 / 审计**——不限制 hook 的出网、不做 hook 触发与结果的持久化审计流水。

## 验收标准
- AC1: 三要素规则——一条含 event + action（+ 可选 if）的 hook 正确加载并触发；缺 event / 缺 action / event 非法 / action 字段不完整均被集中校验报告，缺 if 的无条件触发。（F1）
- AC2: 九种事件识别——`shutdown`/`session_start`/`session_end`/`turn_start`/`turn_end`/`pre_send`/`post_receive`/`pre_tool_use`/`post_tool_use` 均被识别并按各自时刻触发；未知事件名报校验错误。（F2）
- AC3: 四种条件操作符——`==` 精确、`!=` 反向、`=~` 正则（部分匹配）、`=*` glob 各自正确匹配 / 不匹配；glob 的路径语义（`**` 跨目录、`*` 不跨目录）与命令语义正确。（F3）
- AC4: 条件组合二选一——`&&`（全部满足）与 `||`（任一满足）各自正确；同一条件内混用 `&&` 与 `||` 报配置错误。（F3）
- AC5: 四种动作——`command` 执行 shell 并注入上下文环境变量、`prompt` 在对应事件注入上下文、`http` 发请求（含模板替换）、`agent` 未注册执行器时返回明确错误不真实运行。（F4）
- AC6: 工具前拦截——`pre_tool_use` 命中 reject 时工具不执行、拒绝原因作为工具结果回灌、Agent Loop 继续；非 pre_tool_use 事件上的 reject 不生效。（F5）
- AC7: 执行控制——`once` 同会话只触发一次（二次触发为空）、`async` 不阻塞调用方、`timeout` 超时强制终止并判失败；`pre_tool_use` 声明 `async` 报配置错误。（F6）
- AC8: 失败不中断——命令非零退出 / HTTP 失败 / 超时 / agent 无执行器时，动作判失败但不抛出、Agent 主流程继续。（F7/N1）
- AC9: 集中校验与降级——多行非法配置一次性聚合报告（不因首个错误中断）；文件缺失视为空规则集；非法配置不崩溃、不影响会话。（F7/N2）
- AC10: 模板变量替换——动作的 `command`/`message`/`url`/`body` 中 `${event}`、`${tool}`、`${file_path}`、`${message}`、`${args.xxx}` 正确替换为当前事件上下文值。（F4）
- AC11: 不破坏既有章节——多轮连环、权限判定、上下文压缩、Skill 激活仍成立；只读工具批量并发不因 hook 检查退化；临时无头冒烟验证通过、`mvn compile`/`mvn clean package` 成功。（N3/N5）
- AC12: 跨协议一致——anthropic 与 openai（含兼容端点）hook 行为一致；provider 适配层未改动。（N4）
